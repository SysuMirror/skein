# Skein 产品定义

> 一句话、一个闭环、三个工作面。开发取舍以本文为准。

## 一句话

**把真实用户反馈，变成可验收的修复。**

不是"又一个 Agent 平台"，也不是工单后台。Skein 负责一件事：从真实反馈出发，
调度节点上的编码 Agent 完成修复并交付分支，最后由人验收。

## 给谁用

- 小团队的维护者 / 值班人，通常 1–3 个人。
- 每天要回答三个问题：**现在有什么要我处理？谁在干什么？卡在哪？**
- 不假设有专职 SRE、不假设有多租户、不假设有人愿意读长日志。

## 核心闭环

```text
外部反馈（帖子 / 评论 / 对话 / 巡检信号）
      │
      ▼
程序层准入（忽略 / 记账 / 处理）
      │
      ▼
工单（线索归并、去重）
      │
      ▼
派给节点上隔离的编码 Agent 会话
      │
      ▼
交付（分支、提交、diffstat、自测总结、草稿 PR）
      │
      ▼
人验收（通过 / 驳回）
```

人审是硬闸。系统可以自动采集、自动判断、自动执行，**不代替人合入代码**。

## 三个工作面

一级导航三个，回答三个不同的问题：

| 工作面 | 回答什么 | 包含 |
| --- | --- | --- |
| **工作台** | 现在要我做什么 | 待验收、卡住的派工、正在跑的任务 |
| **需求** | 这件事走到哪了 | 工单列表、详情、派发、验收、交付卡片 |
| **运行** | 谁在跑、卡在哪 | 总览拓扑、最近派工、节点、Worker 会话、事件流、信号 |

准入策略、提示词修订这类内部机制不做成面向使用者的页面：它们要么是数据，
要么应该有更合适的操作入口，而不是塞进一个叫"平台"的页面里。

## 不是什么

- 不是聊天机器人：聊天只是可选的入口之一，主界面是工单和运行状态。
- 不是 CI/CD：不代替人合入、不代替人做上线决定；分支和 PR 由人处理。
- 不是通用多租户 Agent 平台。
- 不是监控大盘：指标只保留能直接指向动作的。工作台的阵图是导航——每个点都能点回对象，
  不做装饰性图表。

## 产品原则

1. **一屏回答"现在谁在干什么、卡在哪"。**
2. **每个数字都能点回具体对象。**
3. **系统安静，只有需要人行动时才出现。**
4. **人审是硬闸，按钮旁写清后果。**
5. **空态告诉人下一步做什么，不只说"暂无数据"。**
6. **失败要看得见**：派单失败、建 PR 失败都要在界面和留痕里给出原因，不能静默。
7. **零配置可用**：不配任何可选能力，核心流程也要能完整走通。

## 成功指标

- 从反馈进入到人验收的时间。
- 待验收队列的停留时长。
- 一次验收通过率。
- 派工超时 / 节点离线导致卡住的数量。
- 每天需要人工介入的次数。
